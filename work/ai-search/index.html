AI Search:
Recovering Lost Revenue

“Just type it out. We’ll find what you need.”

On Kurly, one typo could end a shopping trip. I led an AI search that catches what the old engine missed, so every search can lead to a cart.

01 CONTEXT

Search Was Where Kurly Made the Most Money

Kurly is Korea’s premium fresh-grocery unicorn with 3.5M monthly active users. People who search already know what they want, so search drove more revenue than any other part of the app.

But 6.8% of Searches Ended in “No Result” Every Day

Each “No Result” left a user who was ready to buy with two choices: search again and again, or give up on the purchase.

03 ROLE AND RESPONSIBILITY

A Three-Person Team, a Company-Wide Change

  1. Strategy

    Defined the problem and set the project scope. Proposed a simple rule: AI steps in only when the old search finds nothing, so we could ship without touching what already worked.

  2. UX

    Designed the “Beta” notice that tells users which results come from AI, so a new kind of result felt honest, not confusing.

  3. Execution

    Designed the system architecture with the engineers, built a demo page to choose the right data source, designed the A/B test and KPIs, built the monitoring dashboard, and led QA through launch.

  4. Alignment

    Kept the CEO, the search engine team, and the product management team on the same page.

Users knew exactly what they wanted.Search told them it didn’t exist.

04 USER PROBLEM

Tiny Mistakes Left Users Empty-Handed

The old search engine only accepted exact matches, so a typo, an extra space, or a different word for the same thing meant an empty page.

Users were left with a frustrating search experience: guess the “right” spelling, try again, or simply leave.

05 COMPANY’S PROBLEM

Small Fixes Kept the Big Fix Waiting

When a search found nothing or the wrong products, merchandisers and marketers asked the search engineers to fix it. Each fix was a manual keyword update, one request at a time.With the team buried in small fixes, the search engine rebuild, the work that mattered most, kept getting pushed back.

So I asked a different question. ↓

06 DEFINE

How might we turn “No Results” into results,
without rebuilding the search engine?

Objectives and Goals

Long-term goal
Improve Kurly’s search performance and search experience
Short-term goal
Validate the baseline performance and immediate impact of AI search

Key Performance Indicators

User behavior metrics

  • NRRNo-Result Rate
  • CTRClick-Through Rate
  • ATC CVRAdd-to-Cart Conversion Rate
  • CVRPurchase Conversion Rate

Business metrics

  • RPSRevenue per Search
  • Add-to-Cart Value
  • GMVGross Merchandise Value
  • Estimated Gross Margin
  • AI API Cost

Strategic Process

Leadership believed the Bestsellers were enough.
So the plan was to test that belief with real data, prove the engine update was worth it, and then hand the work back to the team that owned search.

  1. 1

    PoC

    Show that similar products convert far better than the Bestsellers on a No-Result search.

  2. 2

    CEO Decision

    Bring the evidence to the CEO and get the go-ahead.

  3. 3

    Improvement

    Tune the AI layer on what the PoC taught us.

  4. 4

    Integration

    Ship it into Kurly’s live search.

  5. 5

    Hand-off

    Pass it to the Search Engine team as part of their roadmap.

Guardrails

Three rules the AI had to follow:

  1. 1

    Only on failure

    AI runs only when the old search finds nothing.

  2. 2

    Narrow scope first

    Typos, spacing, and synonyms only.

  3. 3

    Same business rules

    Every AI result respects Kurly’s business and inventory policies.

Prove it first, build later

First we had to prove that fixing No-Result searches was worth it, fast. So instead of building our own, we added an AI Search SaaS on top of the existing search.

RebuildAdd SaaS

Use what Kurly’s data already sits on

Kurly’s product data already lived in BigQuery on Google Cloud. So we chose Google Cloud’s Vertex AI Search, which plugs straight into that data and matches by meaning, not exact spelling.

Crawl the website, or feed it clean data?

To compare result quality across Kurly’s search engine, web crawling, and structured data, I quickly built a demo dashboard with Gradio. Structured product data gave far more stable results.

08 SEARCH FLOW

AI Search Only Steps In When Search Fails

I designed the flow to keep the search engine team’s work to a minimum. Every search still goes to the old engine first, and only an empty result calls AI Search.
